外部政策环境分析

国产替代 + 数字化政策的叠加，对柯莱特的外部约束与机会窗口

中国未来2—3年更可能落在"渐进式国产替代 + 双栈长期并存"的组合情景，而不是一刀切替代。这对柯莱特意味着：旧项目压力是确定的，新方向窗口是真实的。

🏛️ 自主可控政策

《数据安全法》《网络数据安全管理条例》推动本地部署；金融行业"关键技术自主可控"要求；央企/国企IT采购向国产倾斜。
→ SAP新建项目减少，迁移改造需求增加

高影响

🏭 制造业数字化

工信部"智能制造工程"明确推进MES/WMS/设备联网；工业互联网平台建设提速；制造业研发数字化纳入补贴范围。
→ 制造业解决方案是政策最明确的增量

利好

☁️ 上云与专属部署

数据安全要求推动"专属云/混合云"落地；金山云持股带来天然协同；国有机构倾向"可控云"而非公有云。
→ 上云+迁移项目是柯莱特的协同优势区

利好

💰 预算结构迁移

IT预算没有消失，但采购逻辑变了：从"新系统建设"转向"必须做的合规、迁移、效率"。可证明价值的项目优先获批。
→ 需证明交付价值，而非卖实施资源

中影响

政策结论：柯莱特不是没有空间，但增长来源必须从"国外软件新项目"切换到"行业解决方案 + 国产替换迁移 + 上云本地化"。下一页看AI带来的额外变量。

PART 02 - 续

AI浪潮对柯莱特的影响

不是整体变好或整体变坏——而是把现有差异放大：弱的更弱，强的更强

⚠️ 威胁——为什么是压力

高SAP暴露业务承压

国外企业软件新建项目空间被压缩；客户中长期更偏向自主可控。若未来增长仍押在SAP新建项目，结构性风险会越来越大。

传统ITO/BPO被直接压价

AI提升效率后，客户会主动要求把收益让渡出来。如果仍按"派多少人、算多少人天"计价，AI只会让客户拿来压价，而不是形成利润改善。

旧式金字塔交付组织被削弱

大量低价值协调、文档搬运、状态汇总岗位会被AI压缩70%以上。若组织仍依赖层层协调和人工搬运，AI会先削弱这些岗位的存在合理性。

治理缺陷会被AI放大

文档不标准、知识库混乱、权限体系不清都会直接影响AI输出质量。AI不是自动纠错器；流程和治理越差，放大后的问题越严重。

✅ 机会——为什么是机会

行业方案需求增强

金融、制造、物流持续数字化，但客户更看重本地化、可控、可落地。柯莱特原本就有行业know-how和项目实施能力，容易把"行业理解"转成解决方案收入。

上云、本地化、迁移重构项目增加

数据安全、专属部署、混合云、本地化运维要求提升。柯莱特与金山云组合，天然更容易承接迁移、专属云、统一运维和本地部署项目。

AI放大交付体系价值

大量文档、规则、案例、工单、脚本、测试与知识库可被AI利用。柯莱特非常适合成为"AI增强的行业解决方案与持续运营服务商"——Know-how+AI=壁垒。

ITO有机会做经营模式升级

若把ITO从按人天卖，升级成按结果和服务水平交付，毛利与议价能力都有机会改善。这是公司最先可能体现AI经营价值的业务线。

🧭 管理层需要特别关注两个重点

重点一：SAP线不是"马上消失"

更重要的是存量维护、替换迁移、双轨并行和接口重构。

重点二：ITO线的风险和机会同时最大

不改经营模型，AI会加速被压价；改成结果交付，可能最先体现AI经营价值。

⚡ 核心判断：机会和威胁的分水岭只有一条：有没有把Know-how和AI结合起来。有积累又会用AI的人，机会被放大；有积累但不用AI的人，被动压价；没积累靠AI的人，永远无法复制柯莱特的壁垒。

PART 03

AI能力边界与适用场景

结合柯莱特业务 —— 判断哪些场景值得投入

当今AI的竞争力既来自模型，也来自系统设计。柯莱特应把AI定位为"顾问增强"和"效率工具"，而非替代。

✅ AI现在能做什么

📄 信息理解与表达

阅读长文档、抽取结构化信息、生成报告初稿

→ 举例：SAP蓝图自动摘要 / 合规报告初稿生成 / 金融监管文件解析

💻 编码辅助与测试生成

辅助开发、提速调试、生成样板代码、批量生成测试用例

→ 举例：ITO代码补全提速30-50% / SAP接口自动化测试用例生成

🧠 知识检索与历史匹配

基于30年项目积累的文档、案例、工单进行秒级检索与匹配

→ 举例：金融合规知识问答 / 新问题→历史解决方案秒级匹配

🔄 多步骤任务执行（Agent）

调用工具、执行多步任务、自动化流程

→ 举例：运维工单自动分类+派发 / 代码提交→测试→部署流水线

⚠️ AI仍然做不到（或需人工介入）

🚫 无监督长流程端到端执行

跨部门协调、多轮沟通、需求澄清的长链条任务

→ 举例：SAP实施项目从需求调研到上线交付——AI能做辅助，无法替代顾问主导

🚫 高风险关键决策

合规判断、架构决策、财务审批等必须人工承担最终责任

→ 举例：金融系统改造核心参数决策 / 合规改造方案审批——必须人工签字

🚫 100%准确性要求的工作

AI仍存在"幻觉"，对准确性要求极高的工作必须人工复核

→ 举例：金融合规报告 / 法律文本对照——AI生成初稿，人工确认

🚫 复杂客户关系与谈判

理解客户真实顾虑、处理多方利益、推动复杂谈判

→ 举例：大客户复杂项目谈判——需要顾问情商，不可替代

🧭 判断一个场景是否适合AI的自检四问

① 数据可得吗？
文档、代码、案例是否已整理归档
② 错误代价大吗？
AI出错时人工能否及时发现和纠正
③ 边界清晰吗？
任务能否拆解成AI可执行的步骤
④ 复用价值高吗？
做一次后能复用于多少个项目

⚡ 关键认知

AI本质是概率模型，不是规则引擎。企业真正要管理的是"哪些环节让模型进入流程、用什么数据、接哪些工具、如何复核、如何留痕、如何限权"。

PART 04

AI转型核心问题

先定义问题，再寻找答案 —— 参照v5文档提炼

什么叫AI转型？什么不算？

AI转型不是"是否使用AI工具"，而是公司是否因此改变了价值创造方式、业务交付方式和组织治理方式。

✅ 真正的转型

  • 收入结构发生变化
  • 毛利结构发生变化
  • 交付方式从工时 → 结果/SLA 发生变化
  • 客户价值发生持续变化
  • 组织治理方式发生变化

❌ 不算转型

  • 上线几个聊天机器人
  • 员工用上了AI工具
  • 采购了AI平台
  • 成立了AI部门
  • PPT里加了很多AI元素

⚡ AI转型的六个核心问题（参照v5提炼）

核心问题1：ITO 从人天交付 → 结果交付

不再堆人工，看结果。相同资源池，若能按SLA和结果定价，毛利空间显著扩大。

核心问题2：规模增长 vs 毛利稀释的矛盾

传统ITO：收入增长=上更多人。AI后：高频工作沉淀为模板/自动化，新增收入不必一比一对应新增人数。

核心问题3：交付一致性与人员波动

高度依赖个人经验→质量难标准化；人员流动→一致性下降。AI让组织能力替代个人发挥。

核心问题4：客户按人天付费 vs 供应商按价值收费

客户希望买可控的资源投入；供应商希望体现方法论和结果价值。结果交付才能实现价值定价。

核心问题5：中间协调层价值重定义

汇总、催办、材料搬运类岗位被AI压缩70%以上。这些岗位需要升级为：方案设计者 + 交付设计者。

核心问题6：治理缺陷被AI放大

文档混乱、知识库不标准→AI输出质量差。AI化之前必须先治理，这是前提，不是锦上添花。

柯莱特最适合采用"先内部交付提效，再把成熟能力商品化，最后形成持续服务收入"的路径，而不是一开始追求全自动Agent替代。

PART 04 - 续

为什么柯莱特适合AI增强

基于前文分析的综合结论

分析起点：柯莱特的业务底盘是"企业应用服务 + 行业解决方案 + 大规模交付中心"，这决定了它最适合走"AI增强服务商"路线。

结合Part 02的业务前景分析和Part 03的AI能力边界，可以清晰看出：柯莱特的每一条业务线，都天然拥有让AI发挥最大价值的土壤。

🎯 柯莱特的资产是什么（不是模型）

  • 行业Know-how — 30年积累的规则、案例、监管合规知识——AI让其结构化、可复用
  • 大规模交付体系 — 15个交付中心、数千名技术人员——规模越大，AI提效收益越高
  • 丰富的知识资产 — 文档、工单、代码、测试用例——天然的训练数据
  • 稳定的客户入口 — 金融、制造业、央国企——Know-how+AI=壁垒

⚡ AI能增强的环节（都有对应业务场景）

  • 文档生成与处理 → SAP蓝图摘要、金融合规报告、工单归档
  • 知识检索与复用 → 历史项目经验匹配、新顾问上手加速
  • 代码辅助与测试 → ITO开发提速30-50%、接口自动化测试
  • 运维智能化 → 工单分类/派发、SLA监控、故障知识库
  • 合规检查辅助 → 金融监管报告生成、反洗钱规则匹配

🤝 为什么不是造模型，而是做AI增强

造基础模型的成本：研发投入巨大、竞争激烈、大厂主导、投入周期长、不确定性高

做AI增强的优势：Know-how是护城河、客户关系是入口、规模效应最强、变现路径清晰

柯莱特最大的资产不是技术模型，而是业务理解和客户关系。造基础大模型不是这类公司的核心竞争力，反而会分散资源、错失把现有能力AI化的窗口期。

柯莱特最适合的AI路径："把Know-how从顾问脑子里→系统里→AI里"——让个人能力变成组织能力，让AI成为护城河的放大器，而不是替代品。

考核对象 ❌ 旧逻辑 ✅ 建议调整为

PART 04 - 业务线详解①

SAP/企业应用服务（1/2）

第一梯队 — 国产化替代带来的冲击与机遇

核心判断：这条线正处于"收入结构重排期"——纯SAP新实施项目的机会将逐步减少，而存量维护、升级支持、双轨并行、数据迁移、接口重构、与国产系统的集成改造，以及从SAP向更本地化栈的替换迁移，反而可能阶段性增加。

⚠️ 国产化替代对SAP业务的冲击

政策驱动因素：

  • 2022年银保监会："要坚持关键技术自主可控原则，降低外部依赖、避免单一依赖"
  • 2025年金融监管："再次强调提升科技自主可控能力"
  • 工信部："大力推动自主可控工业软件推广应用，提升产业链供应链自主可控能力"

🔴 短期冲击（新项目减少）

  • 金融客户：新建项目路线图正在变化，更倾向国产方案
  • 国企客户：信创要求下，SAP新建项目审批趋严
  • 关键行业：对单一国外软件依赖持审慎态度

🟢 长期机遇（替换迁移）

  • 存量运维：现有SAP客户需要持续维护支持
  • 升级改造：S/4 HANA升级需求仍存在
  • 数据迁移：从SAP向国产ERP迁移带来新项目
  • 双轨并行：过渡期需要两套系统并行运维

真正危险的不是"有没有SAP客户"，而是"公司是否仍把增长主要押在SAP新建项目上"。收入结构必须从"新建项目规模"转向"存量运维+替换迁移机会"。

金融解决方案（1/2）

第一梯队 — Know-how + AI：把经验变成利器

思考过程：分析金融业务时，我问了自己一个问题——"柯莱特30年在金融领域积累了什么？这些积累能不能被AI放大？"

答案：Know-how是柯莱特在金融领域最核心的差异化资产，而AI是让这份资产价值最大化的工具。

🏦 金融业务韧性来源

  • 合规刚性：金融监管不是削弱数字化，而是提高门槛——"自主可控"≠"不用系统"，而是"要用更合规的系统"
  • 持续投入：关键技术自主可控 → 持续投建 + 本地化合规 + 本地部署
  • 需求稳定：银行、保险、证券都有强制的系统改造周期
  • 转换成本高：金融客户换供应商的摩擦极大，粘性高

💎 柯莱特30年的Know-how积累

  • 柜面系统：无数项目积累的柜面业务流程、合规要求、异常处理
  • 反洗钱：可疑交易识别规则、监管报告格式、案例库
  • 反欺诈：风控规则、模型逻辑、专家经验
  • 核心系统改造：数据迁移、接口适配、并行运维经验
  • 监管合规：各类监管要求、本地化改造、审计支持

为什么Know-how是利器？

金融客户的痛点不是"没有系统"，而是"谁来帮我建、谁来帮我改、出了问题谁能快速响应"。

柯莱特的Know-how → 能听懂客户的问题 → 能给出符合监管要求的方案 → 能快速交付并持续运维

这是新进入者无法复制的优势。

快速复用：新项目遇到类似问题 → AI秒级检索历史方案 → 而不是重新研究

批量处理：合规检查、报告生成、案例匹配 → AI批量处理 → 顾问专注复杂判断

持续进化：每个项目经验 → 自动沉淀 → 知识库越来越丰富 → 越用越聪明

• 合规助手 → 可对金融客户独立售卖
• 监管报告生成服务 → 按量收费
• 行业知识包 → 新员工培训、行业分享

💎 Know-how资产

30年项目经验、监管合规知识、专家规则、案例库、行业模板

🤖 AI增强层

知识抽取 → 智能检索 → 规则匹配 → 报告生成 → 持续学习

📦 价值输出

提效：顾问效率↑ 交付速度↑ | 商品化：合规助手、监管报告、知识服务

制造业应作为第二优先，与SAP/ITO/金融形成差异化的增长主线。重点不是替代现有业务，而是做成可复制的行业解决方案，逐步摆脱对单一软件的依赖。

PART 04 - 业务线详解⑤

通用数字化与物流/BPO

第二/第三梯队 — 轻量处理

☁️ 通用数字化与上云 第二梯队

与金山云协同最强，应作为增量引擎

  • 需求来源：数据安全条例 → 本地部署↑ | 国产替代 → 改造项目↑ | 统一运维 → 持续服务↑
  • AI增强方向：迁移评估自动化、架构设计辅助、运维智能化
  • 策略：承接企业从旧系统到新架构的改造项目，与母公司金山云产品协同

🚚 物流供应链 | 📞 BPO 第三梯队

保留配套，不承载核心叙事

  • 物流：稳健增长，需更明确的场景化产品；AI可做智能调度、路径优化
  • BPO：从"卖人头"升级为"卖SLA与质量"；AI坐席辅助、质检自动化
  • 策略：保留配套，不投入过多资源

PART 04 - 核心内容

24个月落地路线图

从内部提效到形成持续服务收入的节奏设计

与五步思考的关系：五步思考回答的是"先想什么、按什么原则决策"；24个月路线图回答的是"按什么节奏推进、每个阶段交付什么"。前者是决策顺序，后者是执行节奏。

0–3个月：诊断与设计

• 盘点文档、知识库、代码库、工单与案例
• 筛出8–12个高价值场景
• 建立最小AI治理框架
• 确定业务owner
→ 对应：五步思考的"定北极星+划业务+算经济账"

3–9个月：内部提效

• 先在SAP/企业应用、ITO、金融三条线上落地
• 知识问答、文档生成、代码/测试辅助、工单辅助
• 验证方法论，形成可复用的交付模式
→ 对应：五步思考的"定治理+选技术"

9–15个月：对外商品化

• 把成熟能力包装成可卖的AI增强模块
• 交付Copilot、知识助手、运营助手、私有化落地底座
• 开始对外定价和售卖
→ 对应：业务线的商品化定义

15–24个月：持续服务

• 从单次项目收入过渡到"项目 + 订阅/托管/运维"混合模式
• 形成经常性收入
• 优化指标体系，持续迭代
→ 对应：转型成功的财务层指标

PART 04 - 续

治理、风险与前提条件

为什么这些必须先行

📋 数据与知识治理必须先行

没有清洗过的文档、代码、工单和制度库，AI很难稳定输出。这是技术问题，更是管理问题。

⚠️ 明确人工复核边界

高风险判断、审批、财务与合规相关动作必须有人工复核。不能因为用了AI就放松质量控制。

🔧 技术平台要统一

模型接入、检索、日志、评测、权限与私有化部署不应各业务线各做一套，否则无法规模化。

👥 组织机制要双轮驱动

一边由平台团队搭底座，一边由业务owner负责场景落地与结果。缺任何一边都会失败。

💰 奖惩与预算要跟着变

否则AI会停留在"额外工作"而不是"核心工作流"。业务owner必须有动力去推动AI落地，而不是被动等待IT部门交付。
