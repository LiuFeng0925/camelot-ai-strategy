PART 03

AI能力边界

给管理者的系统说明

AI最不适合直接承担"高风险最终决策、无监督长流程执行、绝对正确性要求极高"的工作

✅ AI现在能做什么

  • 信息理解与表达 — 阅读长文档、抽取结构化信息、生成报告初稿
  • 编码辅助 — 辅助开发、提速调试、生成样板代码
  • 多模态处理 — 图像、音频理解与生成
  • Agent能力 — 调用工具、执行多步任务

⚠️ AI仍然做不到

  • 可靠的无监督长流程 — 需要流程、工具和护栏
  • 零错误的关键决策 — 必须有人工复核
  • 实时信息完全准确 — 仍存在"幻觉"问题
  • 复杂业务判断 — 需要行业经验与常识

⚡ 关键认知

AI的本质不是数据库，也不是规则树，而是基于Transformer的大规模概率模型。企业真正要管理的不是"模型聪不聪明"，而是"哪些环节让模型进入流程、用什么数据、接哪些工具、如何复核、如何留痕、如何限权"。

PART 03 - 续

AI适用场景分析

最适合 vs 最不适合

🎯 最佳适用场景

  • 高信息密度 — 文档处理、知识抽取
  • 规则较清晰 — 代码辅助、测试生成
  • 可校验 — 摘要、翻译、格式转换
  • 可拆解 — 多步骤但边界清晰的任务
  • 辅助决策 — 提供选项，人工最终判断

🚫 暂不适用场景

  • 高风险最终决策 — 财务审批、合规判断
  • 无监督长流程执行 — 端到端无人值守
  • 绝对正确性要求极高 — 法律、医疗诊断
  • 实时敏感信息 — 需要100%准确的事实
  • 复杂谈判与关系处理 — 需要人类情商

💡 核心原则

当今AI的竞争力既来自模型，也来自系统设计。企业应该把AI定位为"顾问增强"和"效率工具"，而不是"数字员工替代"。

PART 04

AI转型核心问题

先定义问题，再寻找答案

什么叫AI转型？什么不算？

AI转型不是"是否使用AI工具"，而是公司是否因此改变了价值创造方式、业务交付方式和组织治理方式。

✅ 真正的转型

  • 收入结构发生变化
  • 毛利结构发生变化
  • 交付方式发生变化
  • 客户价值发生持续变化
  • 组织治理方式发生变化

❌ 不算转型

  • 上线几个聊天机器人
  • 员工用上了AI工具
  • 采购了AI平台
  • 成立了AI部门
  • PPT里加了很多AI元素

柯莱特最适合采用"先内部交付提效，再把成熟能力商品化，最后形成持续服务收入"的路径，而不是一开始追求全自动Agent替代。

PART 04 - 业务线详解①

SAP/企业应用服务（1/2）

第一梯队 — 国产化替代带来的冲击与机遇

核心判断：这条线正处于"收入结构重排期"——纯SAP新实施项目的机会将逐步减少，而存量维护、升级支持、双轨并行、数据迁移、接口重构、与国产系统的集成改造，以及从SAP向更本地化栈的替换迁移，反而可能阶段性增加。

⚠️ 国产化替代对SAP业务的冲击

政策驱动因素：

  • 2022年银保监会："要坚持关键技术自主可控原则，降低外部依赖、避免单一依赖"
  • 2025年金融监管："再次强调提升科技自主可控能力"
  • 工信部："大力推动自主可控工业软件推广应用，提升产业链供应链自主可控能力"

🔴 短期冲击（新项目减少）

  • 金融客户：新建项目路线图正在变化，更倾向国产方案
  • 国企客户：信创要求下，SAP新建项目审批趋严
  • 关键行业：对单一国外软件依赖持审慎态度

🟢 长期机遇（替换迁移）

  • 存量运维：现有SAP客户需要持续维护支持
  • 升级改造：S/4 HANA升级需求仍存在
  • 数据迁移：从SAP向国产ERP迁移带来新项目
  • 双轨并行：过渡期需要两套系统并行运维

真正危险的不是"有没有SAP客户"，而是"公司是否仍把增长主要押在SAP新建项目上"。收入结构必须从"新建项目规模"转向"存量运维+替换迁移机会"。

🧱 组件库建设：AI的新价值

组件库是什么？
将项目经验、技术方案、代码模块封装为可复用的标准化组件

AI能做什么？
• 分析历史代码，识别可复用的代码模式
• 基于已有组件，自动组装可交付功能
• 学习项目经验，生成标准化的技术方案

价值：从"每次项目重新开发"→"基于组件库快速组装"

🏗️ 组件库架构

沉淀代码模块、技术方案、架构设计 → 形成可复用的知识资产

🤖 AI增强层

基于组件库 + AI推理 → 自动组装、推荐、优化 → 快速生成可交付功能

📦 交付输出

复用率↑ | 开发周期↓ | 交付质量↑ | 知识沉淀↑

💡 关键判断

ITO的转型节奏：第一批落地——因为数据质量相对好（代码、文档）、场景清晰可量化、转型风险低（内部验证）。

组件库 + AI 的结合，可以让柯莱特从"卖人头"升级为"卖组件 + 卖服务"，大幅提升交付效率和知识复用率。

金融解决方案（1/2）

第一梯队 — Know-how + AI：把经验变成利器

思考过程：分析金融业务时，我问了自己一个问题——"柯莱特30年在金融领域积累了什么？这些积累能不能被AI放大？"

答案：Know-how是柯莱特在金融领域最核心的差异化资产，而AI是让这份资产价值最大化的工具。

🏦 金融业务韧性来源

  • 合规刚性：金融监管不是削弱数字化，而是提高门槛——"自主可控"≠"不用系统"，而是"要用更合规的系统"
  • 持续投入：关键技术自主可控 → 持续投建 + 本地化合规 + 本地部署
  • 需求稳定：银行、保险、证券都有强制的系统改造周期
  • 转换成本高：金融客户换供应商的摩擦极大，粘性高

💎 柯莱特30年的Know-how积累

  • 柜面系统：无数项目积累的柜面业务流程、合规要求、异常处理
  • 反洗钱：可疑交易识别规则、监管报告格式、案例库
  • 反欺诈：风控规则、模型逻辑、专家经验
  • 核心系统改造：数据迁移、接口适配、并行运维经验
  • 监管合规：各类监管要求、本地化改造、审计支持

为什么Know-how是利器？

金融客户的痛点不是"没有系统"，而是"谁来帮我建、谁来帮我改、出了问题谁能快速响应"。

柯莱特的Know-how → 能听懂客户的问题 → 能给出符合监管要求的方案 → 能快速交付并持续运维

这是新进入者无法复制的优势。

PART 04 - 业务线详解③

金融解决方案（2/2）

第一梯队 — AI如何放大Know-how的价值

核心逻辑：AI不是替代柯莱特的Know-how，而是让沉淀的Know-how可以被快速检索、复用和规模化。

过去：顾问靠记忆和经验 → 效率低、可复制性差
现在：AI + Know-how → 快速检索、批量处理、持续学习 → 把个人能力变成组织能力

🔍 AI能增强Know-how的什么环节

知识沉淀：把散落在顾问脑中、文档里、项目里的经验 → 结构化为可检索的知识库

快速复用：新项目遇到类似问题 → AI秒级检索历史方案 → 而不是重新研究

批量处理：合规检查、报告生成、案例匹配 → AI批量处理 → 顾问专注复杂判断

持续进化：每个项目经验 → 自动沉淀 → 知识库越来越丰富 → 越用越聪明

💡 金融AI商品化路径

第一层：内部提效（0-6个月）
• 合规检查AICopilot → 减少顾问重复劳动
• 文档生成助手 → 报告、说明、方案自动起草
• 知识问答 → 监管要求、案例检索

第二层：对外商品化（6-12个月）
• 合规助手 → 可对金融客户独立售卖
• 监管报告生成服务 → 按量收费
• 行业知识包 → 新员工培训、行业分享

💎 Know-how资产

30年项目经验、监管合规知识、专家规则、案例库、行业模板

🤖 AI增强层

知识抽取 → 智能检索 → 规则匹配 → 报告生成 → 持续学习

📦 价值输出

提效：顾问效率↑ 交付速度↑ | 商品化：合规助手、监管报告、知识服务

💡 关键判断

金融业务的AI转型策略：把Know-how从"存在顾问脑子里"变成"存在系统里、被AI放大"。

这样做有两个好处：①顾问效率大幅提升（减少重复劳动）；②柯莱特拥有了可复制的金融AI能力（不依赖具体的人，而是依赖系统）。

PART 04 - 业务线详解④

制造业解决方案

第二梯队 — 政策红利最强的增量方向

核心判断：最有希望承接政策景气度的业务

📈 为什么是增量引擎

  • 政策红利：工信部《制造业数字化转型指南》+ 中小企业数字化赋能方案（2025-2027年）
  • 需求契合：天然契合"降本增效、计划协同、质量改善、设备升级"等企业最关心的话题
  • 可复制性：MES/APS/QMS等模块在不同行业间有一定通用性

🧠 AI增强方向

  • 设备预测维护：传感器数据 + AI模型 → 提前预判故障
  • 工艺优化：历史数据 + AI分析 → 最优参数推荐
  • 质量分析：质检数据 + AI模型 → 缺陷根因定位
  • 生产排程：约束条件 + AI求解 → 最优排产方案

💡 建议

制造业应作为第二优先，与SAP/ITO/金融形成差异化的增长主线。重点不是替代现有业务，而是做成可复制的行业解决方案，逐步摆脱对单一软件的依赖。

PART 04 - 续

治理、风险与前提条件

为什么这些必须先行

📋 数据与知识治理必须先行

没有清洗过的文档、代码、工单和制度库，AI很难稳定输出。这是技术问题，更是管理问题。

⚠️ 明确人工复核边界

高风险判断、审批、财务与合规相关动作必须有人工复核。不能因为用了AI就放松质量控制。

🔧 技术平台要统一

模型接入、检索、日志、评测、权限与私有化部署不应各业务线各做一套，否则无法规模化。

👥 组织机制要双轮驱动

一边由平台团队搭底座，一边由业务owner负责场景落地与结果。缺任何一边都会失败。

💰 奖惩与预算要跟着变

否则AI会停留在"额外工作"而不是"核心工作流"。业务owner必须有动力去推动AI落地，而不是被动等待IT部门交付。
